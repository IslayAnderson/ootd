# OOTD

# Setup

## Requirements
- PHP 8.2+ with `pdo_mysql` and `fileinfo`
- MySQL 8.0.4+ or MariaDB 10.6+ (outfits use `JSON_TABLE`)
- Composer, then `composer install`
- Writable `tmp/` (sessions) and `storage/` (uploaded images) folders in the project root
- PHP `gd` (with JPEG and PNG) and `exif`, for resizing uploads
- Apache with `mod_rewrite` (see `.htaccess`), or any server that sends unknown paths to `index.php`

## Install
Create an empty database and user, then open `/install.php` and enter the database details.
The installer writes `.env`, creates the tables and an `admin` user (email `webmaster@<your domain>`,
password `root`, change it straight away).

Once installed the installer is locked. To upgrade the database after pulling a new version, log in
as an admin, open `/install.php` and press "Upgrade database", or run `php bin/migrate.php` on the
server (add `--app-url=https://your.site` the first time on installs from before 0.7.0).

## .env
'DB_HOST' (a port can be added as `host;port=3307`)
'DB_USER'
'DB_PASS'
'DB_SCHEMA'
'PWD_SEED' generated by the installer, used to pepper passwords, don't change it once users exist
'TINYMCE' TinyMCE licence key, the installer sets `gpl`
'MEDIA_DRIVER' `local` (default) or `s3`
'STORAGE_PATH' optional, where the local driver keeps images (default `storage/`)
'S3_ENDPOINT' 'S3_REGION' 'S3_BUCKET' 'S3_KEY' 'S3_SECRET' for `MEDIA_DRIVER=s3`; add 'S3_PATH_STYLE=1' for endpoints that need `endpoint/bucket/key` addresses
'APP_URL' the site's address, e.g. `https://ootd.example`, set by the installer; public links are built from it, so don't change it once the site is shared
no defaults are assumed

## Background jobs
Photos of deleted posts are cleaned up (and, later, federation is delivered) by background jobs. Run one of:
```
* * * * * php /path/to/ootd/bin/cron.php   # cron, every minute
php bin/worker.php                          # long-running, under systemd or supervisor
```
`/admin` → Jobs shows anything waiting or failed.
